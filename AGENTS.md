# Repository Guidelines

## Project Structure & Module Organization
- `poker_ai/deep_cfr/` is the active full-deck Deep CFR stack. Key files: `deep_cfr.py` (reference loop), `networks.py` (advantage/policy heads), `policy_targets.py` (optional search-distilled policy targets), `buffer.py`, and `cuda/` (Numba kernels + `GPUDeepCFRTrainer`).
- `poker_ai/research/` contains the autoresearch workflow primitives, local evaluation helpers, search-target builders, policy-head calibration utilities, fixed-state resolver benchmarks, promotion blockers, and Slumbot smoke parsers.
- `poker_ai/games/full_deck/` is the canonical 52-card state and feature encoder used for parity checks.
- `scripts/` contains runnable entrypoints: `run_gpu_deep_cfr.py`, `train_slumbot_2p.py`, `play_slumbot.py`, `solver.py`, and diagnostics. Live turn/river solving uses learned range-pruning before CFR.
- `test/unit/` holds fast regression tests such as `test_network_mask.py`, `test_legal_mask_parity.py`, and `test_slumbot_mapping.py`.
- `models/` and `research/` are local artifact directories for checkpoints/LUT data; keep generated binaries out of git. Legacy short-deck/tabular code remains for reference only.
- `reference_code/` is an ignored local checkout area for external poker/research implementations used during audits; only its README is tracked. `reference_code/AlphaNLHoldem` is the current unofficial AlphaHoldem-style public reference checkout and must remain reference-only.

## Mainline Philosophy & Evaluation Boundary
- Active mainline: tabula-rasa local self-play policy/value learning, promoted by self-play checkpoint-league evidence before external evaluation.
- Tabula-rasa means the learner may receive the simulator, public/private observations, legal action masks, and terminal rewards, but not human poker strategy, Slumbot traces, solver-generated policy labels as the default target, or hand-coded tactical rules. R-NaD/NashPG/MMD-style regularized self-play is aligned with this standard because it learns from self-play trajectories and uses game-theoretic RL dynamics to avoid cycling.
- Slumbot is held-out evaluation only. Do not use Slumbot hands, traces, revealed cards, response ranges, action likelihoods, or trace-start states as training data, target labels, curricula, opponent priors, checkpoint selectors, or hyperparameter signals.
- Slumbot trace, response-range, trace-start, action-likelihood, post-hoc calibration, and detached search-target commands are diagnostic-only unless a completed methodology review reframes them as general locally trained mechanisms.
- CFR/search/solver outputs are allowed as small-game truth meters, root-disjoint diagnostics, or optional general policy-improvement operators, but they must not become the whole player or the main supervised training signal unless a methodology review explicitly proves this preserves the tabula-rasa self-play contract.
- AlphaNLHoldem/RLCard is now a separate public reference surface: use it to test whether our neural self-play method can beat the unofficial AlphaHoldem-style 50bb/5-action baseline, but do not confuse that with native 9-action Slumbot evidence.
- Train environment-native candidates for each benchmark surface. Do not project or adapt a native 9-action Slumbot-facing checkpoint into RLCard's 5-action game for promotion; transfer the general training schema, not the checkpoint or action mapping. If a new card/action environment is added, train a fresh model inside that environment and judge it by that environment's own gates.
- Do not copy AGPL AlphaNLHoldem source or weights into tracked project code without explicit license review. Port ideas and build isolated evaluators instead.
- Keep one candidate mechanism active at a time. If a branch needs Slumbot-specific probes or many knobs to look good, retire it as diagnostic evidence and return to the local self-play loop.
- Generic PPO/Rainbow/NFSP-style algorithms should be plugged in through maintained libraries such as Tianshou, RLCard, or OpenSpiel when possible. Only implement native wrappers, observation/action adapters, evaluators, and gates locally.
- Treat policy target-collapse gates as promotion blockers and diagnostic triggers. Do not lower them or add action-specific patches; run root-disjoint public-world/exact-CFR checks to decide whether the mixed policy actually improved.
- Autoresearch must run the research-log drift guard before stale queued work. Repeated local target-consumer/search-label transfer failures block another XDO/NPI target-consumer variant until review; maintained-library RL response-oracle work remains allowed.

## Coding Style & Naming Conventions
- Python with 4-space indentation, type hints, and PEP 8 names (`snake_case` functions/modules, `PascalCase` classes).
- Keep the 9-action contract and feature/legal-mask behavior aligned across CPU, fast, CUDA, and Slumbot integration code.
- Preserve all-in response semantics across CPU, fast, and CUDA states: an unmatched all-in is not terminal until active non-all-in opponents can respond, while matched/no-further-betting all-in states deal to showdown.
- New Deep CFR checkpoints use the 12 public betting-history features by default and save `uses_betting_history=true`; checkpoints without this metadata load with the legacy masked-history contract.
- Avoid ad hoc poker strategy rules; prefer learned policies, regret matching, and principled search.
- Treat policy-only PPO/NFSP/R-NaD pilots as serious falsifiers: if a frozen native full-deck stochastic policy clears duplicate-swapped controls without resolver or explicit belief, simplify toward it; if it fails, resume learned latent belief/search.
- Modern architectures are allowed when they serve the learned-search objective: public-belief encoders, card-set encoders, action-sequence attention, residual trunks, uncertainty heads, and mixed precision are valid if they pass root-disjoint resolver gates.
- Methodology review scopes must include `decision_impact`, `decision_impact_gate`, and `fallback_if_no_decision_impact`. Every new CUDA/search primitive must explicitly connect to stronger root decisions per millisecond or better self-play checkpoint-league strength before it can remain on the mainline.

## Testing Guidelines
- Place isolated logic tests in `test/unit/`; broader flows in `test/functional/`.
- For any action-space, feature, or mapping change, add/update parity tests and include regression coverage.
- For all-in, terminal, or betting-round changes, run `test/unit/test_full_deck_allin_semantics.py`, `test/unit/test_legal_mask_parity.py`, and a CUDA kernel smoke if CUDA kernels are touched.
- For performance changes, report `iters/hour`, `samples/sec`, and `train sec/iter` with command/config used.
- For longer GPU runs, use `--save-every` plus `--auto-compare` so autoresearch evaluates intermediate checkpoints instead of only the final model.
- Slumbot autoresearch gates write per-decision JSONL traces under `autoresearch-session/slumbot_traces/`; inspect those traces only to explain held-out transfer failures, not to create training targets or choose checkpoints.
- Slumbot queueing is self-play-first: before a passed internal checkpoint league with positive lower95 evidence, live Slumbot gates are capped at 50-hand integration smokes. Larger confidence runs must be held-out validation, not optimization targets.
- Slumbot trace decision records must include replayable `full_action_str`. Solver records may keep street-local `action_str` for solver cache semantics, but diagnostics must use `full_action_str` and skip legacy solver snapshots that do not have it.
- Revealed-hand Slumbot range diagnostics are protected public-belief evidence. Negative log-lift versus uniform, especially on turn/river or large absolute pots, blocks more policy tuning until the range-update failure is explained.
- Revealed-hand Slumbot action-likelihood diagnostics localize whether belief failure comes from the opponent-response model. If actual calls/checks are low likelihood while bets are not, do not patch bet sizes; improve opponent-response or belief-state learning and rerun the same trace diagnostic.
- Leave-one-hand-out opponent-response baselines are causal-localization diagnostics only. If an empirical prior beats the model, treat it as evidence of population/action-frequency shift; do not deploy that prior directly without a reviewed learned belief update and held-out trace/range gates.
- Opponent-response probes are diagnostic until held-out mean log-lift beats both the current model and uniform, then improves revealed-hand range likelihood when used only as a learned likelihood. A probe that beats the model but not uniform is mechanism evidence, not integration evidence.
- Explicit opponent ranges are diagnostic scaffolding only. They may localize belief failures, but they must not become the default live opponent model or a Slumbot-derived training source. Any revived range-conditioned mechanism needs a completed methodology review and matched local self-play gates before Slumbot confidence.

If a shallow or latent selector over observable range/search summaries improves mean EV but has weak beat rate or poor cross-trace prediction, do not tune thresholds; move the learned response signal into policy/search training or retire that branch.
